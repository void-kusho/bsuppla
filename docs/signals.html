Signal Taxonomy & Detection Efficacy

This document provides a comprehensive taxonomy of security signals detected by the bsuppla framework, including performance benchmarks and detection efficacy metrics.

1. Overview

The bsuppla framework detects security-relevant artifacts through a multi-category signal taxonomy. Each signal represents a specific type of finding with associated risk characteristics. The detector registry contains 15 detectors across 7 threat categories, achieving ~880K files/second aggregate throughput.

3. ELF Binary Signals

Analysis of ELF (Executable and Linkable Format) binaries provides insight into binary characteristics that may indicate obfuscation or compromise.

Signal Description Analysis Method Severity Latency
elf_suspicious ELF binary with stripped symbols, static linking, or suspicious sections (UPX, packer) ELF header/section parsing (goblin) Medium 3.38 µs
elf_in_unusual_location Executable located outside standard paths (/bin, /usr/bin, /lib) Path prefix matching Low 3.38 µs

3.1 Detection Criteria

  • Stripped Binary: Missing .symtab or .strtab sections
  • Static Binary: No PT_INTERP or PT_DYNAMIC program headers
  • Packed Binary: Section names containing "upx", "packer", "packed"
  • Unusual Location: Path does not start with /bin, /sbin, /usr/bin, /usr/sbin, /lib, /usr/lib, /usr/local/bin, /usr/local/sbin

3.2 Benchmark Details

The ELF detector reads the first 5 MiB of each executable file to parse headers. On a clean filesystem with standard binaries, it correctly suppresses findings via the default allowlist. The 3.38 µs latency includes file open, read, and goblin parsing.

4. Permission Signals

Unix permission analysis identifies potentially dangerous file access configurations. These detectors are the fastest (~5-50 ns) as they operate purely on st_mode from symlink_metadata.

Signal Description Threshold Severity Latency
suid_or_sgid_executable Executable with SUID (4000) or SGID (2000) bit set mode & 0o6000 != 0 High 50.6 ns
world_writable_executable Executable that is world-writable mode & 0o002 != 0 High 5.3 ns
executable_in_writable_dir Executable located in /tmp, /var/tmp, /dev/shm, /run, /var/run Path prefix matching Medium 23.4 ns
hidden_executable Executable with filename starting with '.' Filename starts with '.' Low 30.5 ns
insecure_shadow_permissions /etc/shadow with world-readable or writable permissions Path + permission check High 23.3 ns

9. Severity Classification

Each signal is assigned a severity level based on potential impact and exploitability. The scoring system forms a bounded join-semilattice (see Concepts).

Level Score Signals Count
Critical 5 private_key_candidate, credential_file, crypto_miner_candidate 3
High 4 suid_or_sgid_executable, world_writable_executable, insecure_shadow_permissions, package_manager_config_suspicious, apk_repository_suspicious, apk_key_unusual 6
Medium 3 elf_suspicious, authorized_keys_present, lockfile_suspicious_source 3
Low 2 elf_in_unusual_location, executable_in_writable_dir, hidden_executable, risky_tool_present, startup_script_present 5

9.1 Suspicion Level Calculation

The overall suspicion level is computed by summing individual signal scores:

total_score = Σ signal_score
suspicion_level = 
  if total_score >= 10: "high"
  else if total_score >= 4: "medium"
  else: "low"

9.2 Example Scoring

Findings Scores Total Level
1× Low 2 2 low
1× Medium 3 3 low
1× Medium + 1× Low 3 + 2 5 medium
1× High 4 4 medium
1× Critical 5 5 medium
2× High 4 + 4 8 medium
2× Critical 5 + 5 10 high
1× Critical + 1× High + 1× Medium 5 + 4 + 3 12 high

ATT&CK Technique ID bsuppla Signal(s) Coverage

Malicious Image T1610 crypto_miner_candidate, private_key_candidate, elf_suspicious ✓
Deploy Container T1610.001 All signals (pre-deployment scan) ✓
Container Administration Command T1609 docker_socket_present (PathRule) Partial
Scheduled Task/Job T1053 startup_script_present ✓
Boot or Logon Autostart Execution T1547 startup_script_present, suid_or_sgid_executable ✓
Hijack Execution Flow T1574 elf_in_unusual_location, world_writable_executable ✓
Obfuscated/Stored Files T1027 elf_suspicious (packed/stripped), hidden_executable ✓
Credentials in Files T1552.001 private_key_candidate, credential_file, authorized_keys_present ✓
Unsecured Credentials T1552 insecure_shadow_permissions, world_writable_executable ✓
System Binary Proxy Execution T1218 risky_tool_present (nc, socat, strace) Partial
Resource Hijacking T1496 crypto_miner_candidate ✓

Coverage Summary

12/13 relevant ATT&CK techniques have at least partial coverage. The primary gap is T1609.001 (Container Administration Command - Docker socket exposure), which can be enabled via the commented PathRule in default_registry().
